= Installation
:navtitle: Installation
:description: Install Antora dark mode as a supplemental overlay or composable UI module.

Dark mode is a *slipstream overlay* — it must **not** occupy `ui.bundle.url` when you mix it with another theme.
Reserve `ui.bundle` for your theme (Default UI, architexture-theme, a custom bundle, etc.).

IMPORTANT: link:https://github.com/antora-supplemental/valentus-theme[valentus-theme] already ships *bundled* dark mode in its release `ui-bundle.zip`.
Do **not** layer this overlay on Valentus unless you are composing modules from scratch — use Valentus alone for the full chrome + dark stack.
Coming from the retired **`antora-dark-theme`** package? See xref:legacy-names.adoc[Legacy names & migration].

* link:https://github.com/antora-supplemental/antora-dark-mode/releases[GitHub Releases]
* link:https://antora-supplemental.github.io/docs/[Antora Supplemental docs portal] (extensions registry)

== Choose an install path

[cols="2,3,3", options="header"]
|===
| Path | When to use | `ui.bundle` owner

| xref:#overlay[Supplemental overlay] (recommended)
| Dark mode on Default UI or a theme that does *not* already include it
| Your theme or Default UI (**not** Valentus release bundle)

| xref:ui-modules.adoc[UI module + orchestrator]
| Slot-based inject when the theme owns `head-meta` / `footer-scripts` partials
| Your theme release bundle (compose; skip if using Valentus pre-merged zip)

| xref:#convenience-bundle[Convenience `ui-bundle.zip`]
| Quick start on Default UI only — no other theme
| antora-dark-mode (pre-merged)
|===

[[overlay]]
== Supplemental overlay (recommended)

Point `ui.bundle` at *your* theme or the Default UI, then layer dark mode via `supplemental_files`.

=== From npm (transport)

[source,bash]
----
pnpm add -D antora-dark-mode
----

Copy or merge into *one* supplemental directory (Antora allows only one):

[source,bash]
----
# Example: vendor into site/supplemental-ui (merge with your branding)
cp -r node_modules/antora-dark-mode/supplemental-ui/* site/supplemental-ui/
----

[source,yaml]
----
ui:
  bundle:
    url: https://gitlab.com/antora/antora-ui-default/-/jobs/artifacts/HEAD/raw/build/ui-bundle.zip?job=bundle-stable
    snapshot: true
  supplemental_files: ./site/supplemental-ui
----

WARNING: If your theme also ships `supplemental-ui` partials (`head-meta.hbs`, `footer-scripts.hbs`), merge dark mode hooks into those files or use xref:ui-modules.adoc[UI modules] instead of wholesale replacement.

=== From git (vendor)

[source,bash]
----
cp -r /path/to/antora-dark-mode/supplemental-ui ./site/supplemental-ui
----

Same playbook shape as npm — one `supplemental_files` directory on your theme bundle.

=== Default UI only (no separate theme)

[source,yaml]
----
ui:
  bundle:
    url: https://gitlab.com/antora/antora-ui-default/-/jobs/artifacts/HEAD/raw/build/ui-bundle.zip?job=bundle-stable
    snapshot: true
  supplemental_files: ./node_modules/antora-dark-mode/supplemental-ui
----

See link:../../examples/antora-playbook-overlay.yml[`examples/antora-playbook-overlay.yml`].

[[convenience-bundle]]
== Convenience `ui-bundle.zip` (Default UI only)

GitHub Releases also ship a pre-merged zip (Default UI + dark mode).
Use it only when you do **not** need another theme in `ui.bundle`:

[source,yaml]
----
ui:
  bundle:
    url: https://github.com/antora-supplemental/antora-dark-mode/releases/download/v1.2.0/ui-bundle.zip
    snapshot: true
  supplemental_files: ./supplemental-ui-overrides
----

Pin `releases/download/vX.Y.Z/ui-bundle.zip` in CI.
For floating or Renovate strategies see xref:version-pinning.adoc[Version Pinning].

See link:../../examples/antora-playbook-convenience-bundle.yml[`examples/antora-playbook-convenience-bundle.yml`].

== Build

[source,bash]
----
antora antora-playbook.yml
----

== Verify

Open the built site and use the sun/moon navbar toggle; preference should persist across pages.
