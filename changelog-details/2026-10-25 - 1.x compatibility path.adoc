= 1.x compatibility path (1.5.0)
:navtitle: Compatibility path (2026-10-25)

== What changed

Dark mode moved to https://github.com/antora-supplemental/antora-ui-chassis[antora-ui-chassis]. The npm name `antora-dark-mode` continues there as 2.x, a relabel that installs `@antora-supplemental/color-scheme`, `@antora-supplemental/light-dark-mode` and `@antora-supplemental/default-paint`.

This repository stays as the 1.x compatibility path. It is not archived and nothing is deprecated on npm.

* `lib/index.js` is now an Antora extension. `register` calls `this.getLogger('antora-dark-mode').warn(...)` once per build with the migration text and link, then registers light-dark-mode and default-paint with the same options as 2.x (`navbar`, `toggle`, `toggle_placement`, `follow_system`, `paint`, `color_scheme`; `site.keys.dark_mode_navbar` still sets `navbar`).
* `test/compat.test.js` checks that the warning fires once, through the `antora-dark-mode` logger, includes the migration link, and that options are mapped.
* The release workflow no longer publishes to npm. 2.x is published by the chassis release workflow.
* README, docs and ui-module text now describe the compatibility path instead of a deprecation.

== Warning text

----
antora-dark-mode 1.x is a compatibility path; dark mode moved to antora-ui-chassis. Migrate: npm i -D antora-dark-mode@2 and add "- require: antora-dark-mode" under antora.extensions in your playbook (remove the old UI bundle or supplemental files). See https://github.com/antora-supplemental/antora-ui-chassis/blob/main/docs/modules/ROOT/pages/migrate-dark-mode.adoc
----

== Not carried over

`themed-svg-element.js` and the VCS header partial.
